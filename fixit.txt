## Highest-value remaining improvements

### 1. Installer smoke in CI (release reliability) — DONE (2026-08-07)

Implemented `.github/workflows/installer-smoke.yml`:
- Manual `workflow_dispatch` + nightly schedule (06:00 UTC)
- Builds unsigned Windows NSIS/MSI via `npm run build:tauri:local`
- Runs `smoke:release`, `smoke:msi`, `smoke:installer`
- Uploads installer artifacts; workflow guard in `check-github-workflows.mjs`

Why (historical):
- Local scripts existed, but no CI packaging smoke job.
- Packaging breaks could ship undetected.

Docs:
- docs/IMPROVEMENT_PLAN.md §6
- docs/FEATURE_OPPORTUNITIES.md
- docs/ROADMAP.md

---

### 2. Replace DOM-ID workflow glue with component state

Why:
- Migration overlays are gone, but controllers still drive UI via IDs
  (~110+ getElementById hits).

| File | Approx. uses |
|---|---|
| frontend/src/lib/app/core.ts | ~62 |
| frontend/src/lib/app/setup.ts | ~22 |
| frontend/src/lib/app/search.ts | ~13 |
| archive / advanced rename / properties | smaller |

Progress, modals, search, and archives still look like: find node by id →
set text/HTML/visibility.

Suggested order (one workflow at a time):
1. Progress modal (title / % / item / cancel)
2. Generic modal confirm flow
3. Search + smart-folder controls
4. Archive create/list UI

This matches the “remaining follow-up” in the migration section of the
improvement plan.

---

### 3. Richer transfer progress messaging

Why:
- Backend tracks bytes (progress.rs); UI shows percent + current item only
  (OverlayShell progress modal / updateProgressFlow).
- Roadmap and feature docs still call this out.

Suggested UX:
- Bytes copied / total
- Rate (MB/s)
- Optional ETA
- Clear cancel feedback when a large tree is mid-scan

Low risk, high daily usability for a file manager.

---

### 4. Dual-pane keyboard workflow polish

Why:
- Navigation shortcuts exist (arrows, Alt+arrows, F6 dual-pane toggle, tabs).
- Feature docs still want stronger dual-pane keyboard behavior.

Gaps to consider:
- Explicit focus primary / secondary (e.g. Tab / Ctrl+Shift+←/→ / Alt+1 / Alt+2)
- Cross-pane copy/move shortcuts (active → other pane)
- Status/chrome that always shows which pane is active

---

### 5. Metadata depth (preview / properties) — DONE (2026-08-07)

Implemented unified `get_file_metadata` for PDF / audio / video (MP4 family) /
Office packages, with size caps. Properties panel shows Details + Metadata
grids; image EXIF path retained.

Why (historical):
- metadata.rs was mainly image EXIF.
- Opportunities doc listed richer media/document panels.

Incremental path completed:
- PDF page count / title
- Audio tags
- Video dimensions/duration (MP4/M4V/MOV)
- Office basic props
- Size/time limits so large files stay safe

---

### 6. Mapped network drive error UX

Why:
- Drive listing already surfaces mapped names and some unavailability text
  in drives.rs.

Opportunity:
- Clearer UI for disconnected maps, permission failures, slow UNC paths
  (timeouts, retry, “offline” badge).
