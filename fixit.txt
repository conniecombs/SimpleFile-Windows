## Highest-value remaining improvements

### 1. Installer smoke in CI (release reliability) — DONE (2026-08-07)

Implemented `.github/workflows/installer-smoke.yml`:
- Manual `workflow_dispatch` + nightly schedule (06:00 UTC)
- Builds unsigned Windows NSIS/MSI via `npm run build:tauri:local`
- Runs `smoke:release`, `smoke:msi`, `smoke:installer`
- Uploads installer artifacts; workflow guard in `check-github-workflows.mjs`

Why (historical):
- Local scripts existed, but no CI packaging smoke job.
- Packaging breaks could ship undetected.

Docs:
- docs/IMPROVEMENT_PLAN.md §6
- docs/FEATURE_OPPORTUNITIES.md
- docs/ROADMAP.md

### 2. Replace DOM-ID workflow glue with component state — PARTIAL (2026-08-07)

Completed slices 1–2 (highest-impact overlay controllers):

1. **Progress modal** — component-owned via `progressUi.svelte.ts` +
   `ProgressModal.svelte`. Core `showProgressFlow` / `updateProgressFlow` /
   `hideProgressFlow` write state, not DOM. Cancel is owned by the component.
2. **Generic modal** — `modalUi.svelte.ts` + `GenericModal.svelte` for
   confirm/prompt/html dialogs and Settings. HTML bodies still go through
   `ModalBody` + `sanitizeModalHtml`. No more `innerHTML` / button wiring in
   `core.ts` or settings open path in `setup.ts`.

Still DOM-ID driven (follow-up slices):
3. Search + smart-folder control chrome (inputs / results header)
4. Archive create/list overlays (and advanced-rename, quicklook IDs)

Why (historical):
- Controllers drove progress/modals via getElementById on OverlayShell markup.

### 3. Richer transfer progress messaging — DONE (2026-08-07)

Implemented richer transfer progress in the component-owned progress UI:

- Size preflight ("Calculating size…") so totals are known early
- Bytes copied / total, smoothed rate (B/s–TB/s), and ETA
- Indeterminate bar while preparing (total still unknown)
- Cancel keeps the dialog open with **Cancelling…** until the backend
  acknowledges or a safety timeout fires
- Current item shows basename (full path in tooltip)

Key files:
- `frontend/src/lib/app/progressUi.svelte.ts`
- `frontend/src/lib/components/ProgressModal.svelte`
- `frontend/src/css/modules/modal.css`
- `src-tauri/src/progress.rs` (estimate + cancel-friendly walk)

### 4. Dual-pane keyboard workflow polish — DONE (2026-08-07)

Implemented dual-pane keyboard and chrome polish:

| Shortcut | Action |
|---|---|
| F6 | Toggle dual pane |
| Tab | Switch active pane (when dual pane on) |
| Alt+1 / Ctrl+Shift+Left | Focus left pane |
| Alt+2 / Ctrl+Shift+Right | Focus right pane (enables dual pane if needed) |
| Ctrl+Alt+C | Copy selection to other pane |
| Ctrl+Alt+M | Move selection to other pane |

Also:
- Active pane inset accent + header tint in dual-pane mode
- Click pane chrome to activate
- Status bar shows **Left pane** / **Right pane** + active path
- Help modal + Settings shortcut list include Dual Pane section

---

### 5. Metadata depth (preview / properties) — DONE (2026-08-07)

Implemented unified `get_file_metadata` for PDF / audio / video (MP4 family) /
Office packages, with size caps. Properties panel shows Details + Metadata
grids; image EXIF path retained.

Why (historical):
- metadata.rs was mainly image EXIF.
- Opportunities doc listed richer media/document panels.

Incremental path completed:
- PDF page count / title
- Audio tags
- Video dimensions/duration (MP4/M4V/MOV)
- Office basic props
- Size/time limits so large files stay safe

---

### 6. Mapped network drive error UX — DONE (2026-08-07)

Implemented clearer mapped-network UX:

**Backend (`drives.rs`)**
- 3s timeout on network probe so dead maps no longer hang drive listing
- Timeout → `offline` with explicit “timed out / check VPN / retry” detail
- Existing Windows errors still map to offline/stale with actionable copy

**Frontend**
- Offline / Stale badges on My PC tree roots
- Richer descriptions (access denied, not ready, timed out, share path)
- My PC **refresh drives** control (↻) re-probes mappings
- Opening an offline mapped drive shows reconnect dialog with Retry
- Failed open refreshes drive status so badges stay current

Key files:
- `src-tauri/src/drives.rs`
- `frontend/src/lib/components/layout-shell/SidebarShell.svelte`
- `frontend/src/lib/components/tree-view/TreeView.svelte`
- `frontend/src/lib/app/core.ts` (`refreshDrives`, reconnect dialog)
- tree/sidebar/modal CSS
